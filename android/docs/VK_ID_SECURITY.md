# VK ID: безопасность ключа и граница «тест / публичный релиз»

Документ про то, что **доказано**, что **не проверено** и что должен решить владелец. Значений секретов здесь нет и быть не должно.

## Коротко
- Защищённый ключ VK ID (`VK_CLIENT_SECRET`) по текущей конфигурации SDK подставляется в `AndroidManifest.xml` приложения через `manifestPlaceholders["VKIDClientSecret"]`. Значит, если ключ передан при сборке, он оказывается внутри APK и читается распаковкой APK.
- Поэтому любой APK с ключом — **только для тестов в закрытом кругу**. Публичная раздача такого APK недопустима, пока VK не подтвердит допустимость этой схемы.
- Репозиторий `Grad620/Kontakt` сейчас публичный. Артефакты Actions публичного репозитория могут быть доступны другим пользователям. Это значит, что тестовый APK с ключом нельзя считать приватным.
- Работает ли вход на телефоне — **не проверено**. Сборка и проверки CI этого не доказывают.

## Где ключ и где его нет
| Место | Ключ внутри? | Как проверено |
|---|---|---|
| `BuildConfig` | нет (туда идут только `VK_CLIENT_ID`, `VK_SCOPES`, `VK_ID_CONFIGURED`) | проверка сгенерированного кода должна выполняться CI |
| Исходный код и коммиты | значения не должны быть записаны | конфигурация читает переменные окружения / свойства Gradle |
| Логи CI | значение не должно печататься | шаги не должны выводить секрет |
| Манифест собранного APK | **да, если VK_CLIENT_SECRET задан** | выводится из `manifestPlaceholders`; отдельную проверку значения не делаем, чтобы не раскрывать его в логах |

## Два режима
| | Тест в закрытом кругу | Публичный релиз |
|---|---|---|
| Что раздаётся | debug-APK | подписанный release-APK |
| Ключ в APK | да при текущей конфигурации | **недопустимо** в текущей схеме до подтверждения VK |
| Кто может скачать | только владелец / доверенные; для этого репозиторий должен быть приватным или APK передаётся лично | любой |
| Что нужно | приватное распространение и план смены ключа после тестов | решить вопрос защищённого ключа |

## Что защищает правило сборки
- `app/build.gradle.kts`: сборки типа **release** (`assembleRelease`, `bundleRelease`, `packageRelease`) блокируются, если передан `VK_CLIENT_SECRET`, а владелец не задал `KONTAKT_VK_KEY_PRIVATE_ONLY=yes`. Debug-сборки, lint и unit-тесты не затрагиваются.
- `KONTAKT_VK_KEY_PRIVATE_ONLY=yes` — это подтверждение владельца, а не техническая защита. Не выставляйте его для публичной публикации APK.
- Это правило не делает ключ безопасным и не закрывает уже собранные debug-артефакты в публичном репозитории.

## Что должен сделать владелец
1. Сделать репозиторий приватным: GitHub → репозиторий → Settings → Danger Zone → Change repository visibility. Либо, если он останется публичным, связаться с VK насчёт смены защищённого ключа и удалить доступные артефакты, содержащие старый ключ.
2. До решения по ключу не создавать теги `v*` и не публиковать релизы.
3. Проверить в кабинете VK ID тип приложения, Client ID, пакет Android и SHA-1 подписи.
4. Установить тестовый APK на телефон и проверить полный вход: открывается ли окно VK, возвращается ли пользователь в Kontakt и какая ошибка появляется.

## Параметры для сверки
| Параметр | Ожидаемое значение | Где задано |
|---|---|---|
| Пакет Android | `com.kontakt.app` | `defaultConfig.applicationId` |
| SHA-1 подписи (debug) | должен совпасть с сертификатом фактически собранного APK | `app/debug.keystore` |
| SHA-1 подписи (release) | зависит от release-ключа из секретов CI | `ANDROID_SIGNING_*` |
| ID приложения | ID именно проекта VK ID | `VK_CLIENT_ID` |
| Схема перенаправления | `vk<ID приложения>` | `VKIDRedirectScheme` |
| Хост перенаправления | `vk.ru` | `VKIDRedirectHost` |

## Что ещё блокирует подтверждение
- Реальный вход на устройстве не проверен.
- Совпадение настроек кабинета VK ID недоступно для проверки из репозитория.
- Необходимо подтвердить официальной документацией VK, разрешено ли использовать защищённый ключ в публично распространяемом Android APK.
