# Сравнение авторизации сторонних клиентов VK

Дата проверки: 22 октября 2026 года.

## Что видно в открытом исходном коде

### VKMes (Hocopor/VKMes)

Исходник: https://github.com/Hocopor/VKMes

В `AuthViewModel.kt` клиент использует `com.vk.api.sdk.VK` и запускает `VK.login(activity, vkScopes)` из старого официального Android SDK. Запрашиваются `MESSAGES`, `FRIENDS`, `PHOTOS`, `DOCS`, `STATUS` и другие разрешения. Это отличается от Kontakt, где сейчас применяется VK ID SDK и OAuth 2.1.

Репозиторий также содержит резервный вход через логин/пароль. Kontakt не должен копировать этот механизм: пароль нельзя принимать или обрабатывать внутри клиента; вход должен проходить на стороне VK.

Важно: README стороннего проекта сам по себе не доказывает, что его методы сейчас работают для нового приложения или что VK одобрил все права. Нужен тест с реальным приложением и официально полученным токеном.

### Официальные SDK

- Новый VK ID Android SDK: https://github.com/VKCOM/vkid-android-sdk — авторизация VK ID по OAuth 2.1.
- Старый официальный VK Android SDK: https://github.com/VKCOM/vk-android-sdk — описывает создание приложения типа Standalone, регистрацию Android-пакета/сертификата и вход через `VK.login`.

## Вывод для Kontakt

1. Разница между VK ID и старым Android SDK — реальная гипотеза, которую нужно проверить. Это не гарантия, что переход автоматически откроет сообщения.
2. Перед миграцией нужно проверить в кабинете VK, может ли приложение Kontakt быть зарегистрировано как Standalone и добавить SHA-1 подписи текущей debug-сборки.
3. Затем на тестовой сборке проверить `users.get`, `messages.getConversations`, `newsfeed.get` и `friends.get` по одному, записывая только HTTP/API-код и название метода, но никогда не токен.
4. Если старый официальный SDK выдаёт токен, но метод по-прежнему возвращает 1051/ошибку прав, не обходить это чужими токенами, паролями, cookie или приватными endpoint'ами: зафиксировать ответ и запросить у VK разрешение для приложения.
5. Музыка VK требует отдельной проверки: публичный `audio.*` API давно недоступен сторонним приложениям. Не обещать VK-плеер без подтверждённого официального доступа.

## Тестовая миграция авторизации (22 октября 2026)

Kontakt подключает официальный классический VK Android SDK (`com.vk:android-sdk-core`) и отдельный ID приложения типа Standalone. SDK credential storage передан в `TokenStore`, чтобы значения шифровались AES-GCM ключом Android Keystore, а не сохранялись в стандартном хранилище SDK. Для проверки требуется зарегистрировать Android package `com.kontakt.app`, SHA-1 используемой подписи и секрет сборки `VK_STANDALONE_APP_ID`. Это эксперимент, не гарантия доступа ко всем методам: после сборки нужно проверить реальные ответы `users.get`, `friends.get`, `newsfeed.get` и `messages.getConversations`; аудио API требует отдельной проверки.
